# Privacy Policies

Public privacy policies for apps published by [SkrChowdhury](https://github.com/skrchowdhury),
served by GitHub Pages so each app has a stable, public URL for its Play Store
listing.

**This repository must stay public.** Google Play stores the privacy policy URL
on the listing and re-checks it over time — an app whose policy URL starts
returning 404 can be *removed*, not merely rejected. Keeping the policies here,
separate from each app's source, means the app repositories can be private
without taking the policies offline.

## Page structure

Each policy page is standalone HTML sharing `assets/style.css`:

- header with icon and package name
- `.meta` block — app, package, platform, version the policy applies from
- `.callout` — the short version, readable in ten seconds
- `.glance` table — mirrors the Play *Data safety* form answers exactly
- `.toc` — numbered contents
- numbered sections, ending with a dated change log and a contact address

Keep the `.glance` table and the Play Console declaration in sync. If they ever
disagree, one of them is a bug.

## Adding an app

1. `mkdir <app-slug>` and copy the closest existing `index.html` into it
2. Drop a 512×512 icon at `assets/<app-slug>.png`
3. Update the header, title, `.meta` block, `.glance` table and the body
4. Add a card to `index.html` and a column to its comparison table
5. Add a row to the table above
6. Commit and push — Pages redeploys within a minute

## Writing an accurate policy

The five policies here differ because the apps differ, and the differences are
the parts a reviewer actually checks. Verify each of these against the source
rather than copying a template:

- **Permissions** — read the *merged release* manifest, not just
  `src/main/AndroidManifest.xml`. Library manifests merge their own permissions
  in, so the shipped app can declare permissions that appear nowhere in the app's
  own manifest. `VIBRATE` reaches all three offline apps this way, from
  `react-native-haptic-feedback`. Checking only the main manifest is how two of
  those pages came to claim "no permissions at all", which was wrong.
  `aapt2 dump permissions app-release.apk` is the definitive answer.
- **No `INTERNET` is a strong claim, so make it precisely.** `GPA Calculator BD`
  declares `INTERNET` only in the *debug* manifest for the Metro dev server, so
  its release build declares no `INTERNET`. CNG দরদাম declares it in `src/main`
  but strips it with a release-type `tools:node="remove"`, so its release build
  declares none either — in both cases say "the released build", not "the app".
  শব্দ খেলা no longer qualifies: since cloud save it declares `INTERNET` in
  `src/main`, so it ships in the release build. When a permission exists but is
  used only for an opt-in feature, say exactly that instead of claiming it is
  absent — the claim has to survive `aapt2`.
- **Local storage** — MMKV, AsyncStorage, SQLite and files all count as data
  kept on the device. List what is stored, and say it never leaves.
- **`android:allowBackup`** — if it is `true` (the Android default), the OS may
  copy app data to the user's Google Drive. That is disclosable, and it is the
  single most commonly missed item. `BDT Rate Today` and CNG দরদাম set it to
  `false`; the other two leave it on and ship `backup_rules.xml` /
  `data_extraction_rules.xml`, which say exactly what is included.
- **Export and share** — a document picker or share sheet sends a file wherever
  the *user* chooses. Say that it is user-initiated and that nothing uploads on
  its own.
- **Network calls** — list every host the app contacts, what each is for, and
  what the request carries. Grep the `src/api` layer for literal URLs.
- **Ad and analytics SDKs** — check `package.json` dependencies, not source
  greps. Searching for "tracking" hits typographic letter-spacing tokens.
- **If an app does show ads, say so first, not last.** জমি হিসাব is the only one
  here that does. Its page puts AdMob in the opening callout and gives it a full
  section: what Google receives (advertising ID, device data, IP-derived coarse
  location), what it does not (nothing from inside the app), and how to switch
  personalisation off. "The developer collects nothing" stays true and is worth
  saying, but on its own it would be misleading — the honest claim names who
  *does* receive something. The index page's cross-app wording had to be
  reworded for the same reason when this app was added.
- **Name the origin of every merged permission.** An ads SDK contributes eight
  of জমি হিসাব's nine, so its table has a "comes from" column. A reader can then
  match the list against `aapt2` line by line, which is the whole point.
